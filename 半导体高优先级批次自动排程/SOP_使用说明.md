## 1. 系统是干什么的

排程调度系统用于：给定一批在制批次（Lot）、每个产品的工艺流程、设备资源、班次、Q-time 等条件，**自动排出每个 Lot 在每个步骤上的开始/结束时间，并分配到具体设备**，最后输出排程报表、甘特图和 Excel。

一句话理解：**输入是"数据表"，输出是"排程计划"。** 所以日常维护的核心工作都在 `data/` 里的数据表上。

## 4. 核心数据表详解（每个都带示例）

### 4.1 `lot_list.csv` —— 待排程批次清单【最关键，每天必维护】

**用途**：告诉系统"现在有哪些批次要排"。系统为这里的每个 Lot 生成完整的排程计划。

**列说明**：

| 列名             | 含义        | 说明                                 |
| -------------- | --------- | ---------------------------------- |
| `lot_name`     | 批次号       | 唯一标识                               |
| `carrier_id`   | 载具号       | 备注用，可空                             |
| `product_name` | 产品名       | 必须与 flow/step\_ct 中的产品一致           |
| `qty`          | 片数        | 1\~13，用于查 CT                       |
| `priority`     | 优先级       | 格式 `外部-内部`，如 `1-1`（数字越小越优先）        |
| `step_name`    | 当前所在步骤    | 排程从这里开始往后续排                        |
| `target_step`  | 目标步骤      | 可空；填了只排到该步为止                       |
| `lot_state`    | 状态        | `wait`=等待排程；`running`=已在机台上运行      |
| `running_time` | 已运行时间（分钟） | 仅 `running` 状态用；用于计算当前这步还剩多久结束     |
| `start_time`   | 计划开始时间    | 可空；格式 `YYYY/MM/DD HH:MM`，填了则从该时刻起算 |
| `planned_end`  | 目标交期      | 可空；填了报表会统计是否延期                     |

> 提示：`running_time` 单位是**分钟**，且只在 `lot_state=running` 时有效；它不影响开始时间，只用于缩短当前步骤的剩余时间。若已运行时间 ≥ 本步 CT，系统会自动按 0 处理（说明该步已跑完）。

**示例（2 行）**：

| lot_name | carrier_id | product_name | qty | priority | step_name | target_step | lot_state | running_time | start_time | planned_end |
| ------- | --------- | ----------- | --- | -------- | --------- | ----------- | --------- | ------------ | ---------- | ----------- |
| PC1 | PFME0307 | A005-P1 | 1 | 1-1 | A005-P1-FC-DUMMY | | wait | 0 | 2026/8/17 8:30 | |
| real1 | PFME0408 | A005-MA | 2 | 3-1 | A005-R1-AB1IQC-WFS | | running | 45 | 2026/8/17 8:30 | 2026/8/20 18:00 |

解读：

* 批次 `PC1`：A005-P1 产品、1 片、优先级 1-1（最高）、当前在 `A005-P1-FC-DUMMY`、等待排程、计划 8/17 8:30 开始。

* 批次 `real1`：正在机台上跑（running），已经跑了 45 分钟，排在 `A005-R1-AB1IQC-WFS` 这步，要求 8/20 18:00 前完工（交期）。

***

### 4.2 `flow.csv` —— 产品工艺流程

**用途**：定义每个产品从进料到出货要经过哪些步骤、每步能在哪些设备上做、属于哪个工站（stage）。

**列说明**：

| 列名             | 含义   | 说明                           |
| -------------- | ---- | ---------------------------- |
| `product_name` | 产品名  | 与 lot\_list 一致               |
| `step_number`  | 步骤序号 | 决定先后顺序，如 `10.001`、`20.001`   |
| `step_name`    | 步骤名  | 全系统唯一的步骤标识                   |
| `stage_name`   | 工站/段 | 如 AB1-IQC、AB1-FC，用于分类        |
| `eqp_id`       | 可用设备 | 逗号分隔，多个设备表示该步可在任一台做；留空表示不限设备 |

**示例（3 行）**：

| product_name | step_number | step_name | stage_name | eqp_id |
| ----------- | ----------- | --------- | ---------- | ------ |
| A005-MA | 10.001 | A005-R1-AB1IQC-WFS | AB1-IQC | |
| A005-MA | 20.001 | A005-R1-FC-REFLOW | AB1-FC | PKCON001,PKCON002,PKCON003 |
| A005-MA | 20.002 | A005-R1-FC-DEFLUX | AB1-FC | PKFCV001 |

解读：A005-MA 产品的第 10 步（IQC 检查）不限设备；回流焊 `FC-REFLOW` 可以在 PKCON001/002/003 三台中任意一台做；去 flux 只能上 PKFCV001。

> 新增/修改产品流程后，若对应步骤在 `step_ct.csv` 缺 CT，系统会按同工站已有 CT 自动补全并回写，无需手工补全。

***

### 4.3 `step_ct.csv` —— 加工时间 CT

**用途**：定义每个步骤加工 1\~13 片分别需要多少分钟，系统据此算每个步骤的占用时长。

**列说明**：

| 列名             | 含义        |
| -------------- | --------- |
| `product_name` | 产品名       |
| `step_number`  | 步骤序号      |
| `step_name`    | 步骤名       |
| `qty`          | 片数（1\~13） |
| `step_ct`      | 加工时间（分钟）  |

**示例（2 行）**：

| product_name | step_number | step_name | qty | step_ct |
| ----------- | ----------- | --------- | --- | ------- |
| A005-MA | 10.004 | A005-R1-AB1IQC-INSP | 3 | 3.6 |
| A005-MA | 10.004 | A005-R1-AB1IQC-INSP | 8 | 7.8 |

解读：`AB1IQC-INSP` 这一步，3 片要 3.6 分钟，8 片要 7.8 分钟。若 Lot 是 5 片而表里没有 5 片，系统会自动按相邻片数线性插值。

***

### 4.4 `qtime.csv` —— Q-time 等待时间上限

**用途**：某些工艺规定"上一站出来后，必须在下一次加工开始前完成，超过 N 分钟就报废/异常"。系统排程时会**保证这段等待不超过上限**，超不出时报 Q-time 告警。

**列说明**：

| 列名                 | 含义                                    |
| ------------------ | ------------------------------------- |
| `product_name`     | 产品名                                   |
| `Q-time_start`     | 计时起点步骤                                |
| `Q-time_end`       | 计时终点步骤                                |
| `Q-time_start_mod` | 起点取"track out(离开机台)"还是"track in(上机台)" |
| `Q-time_end_mod`   | 终点取 track out 还是 track in             |
| `Q-time`           | 允许的最大间隔（分钟）                           |

**示例（1 行）**：

| product_name | Q-time_start | Q-time_end | Q-time_start_mod | Q-time_end_mod | Q-time |
| ----------- | ------------ | ---------- | ---------------- | -------------- | ------ |
| A005-MA | A005-R1-UF-DISPENSE | A005-R1-UF-CURE | track out | track in | 240 |

解读：A005-MA 产品，从 `UF-DISPENSE` 这台机台**离开**（track out）到 `UF-CURE` 这台机台**上机**（track in）之间，最多只能隔 240 分钟（4 小时），否则违反工艺。

### 4.4.1 Q-time 排程与"安全站点"原则

当产品存在 Q-time 工序链时（如上例 DISPENSE→CURE 4 小时），区间**前一个**步骤（如 DISPENSE）可视为**安全站点**。系统在排整条工序链时遵循以下原则：

1. **机台空闲且步骤该做时就直接做**：从链首逐步**正向贪心**，为每个步骤找最早已可行的槽位，各步骤**尽早开始**，避免"为了凑下站的 Q-time 而倒着拖着前面步骤"导致明明设备空闲却不做。
2. **只在 Q-time 区间入口做前瞻**：进入区间前估算"要不要进、进去后冲突怎么排"，并把区间参考时刻估准（计入手动延后/精确锁定等约束），做到"能松则松、该等则等"。
3. **超 Q 才回退保底**：仅当贪心结果会导致超 Q-time 时才回退到"倒排保底"，最终保证不超 Q-time。

一句话：**做完当前站点就继续往下做，各步骤越早开始越好；只在 Q-time 区间的入口额外考虑是否进入及冲突处理，不做无意义的倒排导致设备空闲。**

## 5. 进阶数据表详解（每个都带示例）

### 5.1 `priority_wait.csv` —— 优先级对应的步间等待

**用途**：规定不同优先级批次在步骤之间要等多久（作为步间间隔）。优先级数字越小越优先，等待越短。

**列说明**：`ext_priority`（外部优先级）、`int_priority`（内部优先级）、`wait_time`（等待分钟）。

**示例（2 行）**：

| ext_priority | int_priority | wait_time |
| ------------ | ------------ | --------- |
| 1 | 1 | 10 |
| 3 | 5 | 32 |

解读：外部=1、内部=1（最优先）的批次，步骤间只等 10 分钟；外部=3、内部=5 的批次要等 32 分钟。

***

### 5.2 `special_lot_step.csv` —— 某 Lot 某步的特殊覆盖

**用途**：某个特定批次在某一步，工艺上要求用**特殊 CT** 或**限定指定设备**，与 step\_ct/flow 默认不同时用这张表覆盖。

**列说明**：

| 列名            | 含义                     |
| ------------- | ---------------------- |
| `lot_name`    | 批次号                    |
| `step_name`   | 步骤名                    |
| `special_ct`  | 覆盖的加工时间（分钟），留空=沿用默认 CT |
| `special_eqp` | 限定可用设备（逗号分隔），留空=不限     |

**示例（2 行）**：

| lot_name | step_name | special_ct | special_eqp |
| -------- | --------- | ---------- | ----------- |
| CPU先导 | A008-R1-DPS-MOUNT | 45 | |
| DDR1 | A009-R1-DPS-LG | 120 | |

解读：批次 `CPU先导` 在 `A008-R1-DPS-MOUNT` 这步固定用 45 分钟（覆盖默认 CT）；批次 `DDR1` 在 `A009-R1-DPS-LG` 用 120 分钟。

***

### 5.3 `special_eqp.csv` —— 设备批处理（合批 / 限量）

**用途**：某些设备可以一次承载多个 Lot（如固化炉、电镀槽、清洗槽）。用 `together` 开关区分两种批处理方式：

* **together=true（恒组批，强制同时开始）**：满足条件的多个 Lot 会被凑成一批，**全部同一时刻开始**，且设备在一次作业期间锁定、结束前不接受新批（max\_lots / max\_qty 作为一批的上限）。适合必须整批进炉、整批进槽的工艺（如烘烤、电镀）。

* **together=false（软限制，可有先有后）**：**不要求同时开始**，多个 Lot 可以各自先后、部分重叠地在设备上并行作业；仅用 `max_lots`（同一时刻最多几个 Lot）、`max_qty`（同一时刻最多总片数）限定额外并发。槽位满时，后到的 Lot 等最早那一个结束再上。适合可多批次混用、但同时在机数量有限的设备。

**列说明**：

| 列名         | 含义                                        |
| ---------- | ----------------------------------------- |
| `eqp_name` | 设备名                                       |
| `max_lots` | 设备一次承载的 Lot 数上限（true=一批内 / false=同时并发）    |
| `max_qty`  | 片数上限（true=一批内 / false=同时并发）               |
| `together` | `true`=合批同时开始并锁定设备；`false`=不强制同时，可多批次先后并行 |

**示例（2 行）**：

| eqp_name | max_lots | max_qty | together |
| -------- | -------- | ------- | -------- |
| PKPOV001 | 4 | 8 | true |
| PKUFD005 | 3 | 6 | false |

解读：

* `PKPOV001`（固化炉，together=true）：最多凑 4 个 Lot、合计 8 片，必须同批同时进炉；本次烘烤结束前不接受新批。

* `PKUFD005`（together=false）：不强制同时，多个 Lot 可先后上机并行，但同一时刻最多 3 个 Lot、合计最多 6 片；满后就等最早的那个结束、让出位置再上新。

> 注意：合批/并行时系统会校验，同一组内的 `product_name` 与 `step_name` 必须相同（否则无法共享同一设备步骤），不同产品/步骤不会混在一起。

***

### 5.4 `eqp_constraint.csv` —— 设备不可用时间段

**用途**：设备在固定时段不可用（如夜班停机、保养、点检），此时段内不给该设备排程。

**列说明**：

| 列名                   | 含义                              |
| -------------------- | ------------------------------- |
| `eqp_name`           | 设备名                             |
| `no_used_start_time` | 不可用开始时刻（HH:MM）                  |
| `no_used_end_time`   | 不可用结束时刻（HH:MM），跨天可写 0:00 表示次日零点 |
| `date`               | 空=无效；`-1`=每天；`YYYY/MM/DD`=指定某天  |
| `week`               | 空=无；`1~7`=周一\~周日                |

**示例（2 行）**：

| eqp_name | no_used_start_time | no_used_end_time | date | week |
| -------- | ------------------ | ---------------- | ---- | ---- |
| PKCON001 | 22:00 | 0:00 | -1 | |
| PKCON001 | 0:00 | 8:30 | -1 | |

解读：`PKCON001` 每天（date=-1）晚上 22:00 到次日 0:00、以及 0:00 到早上 8:30 都不可用，即只在 8:30\~22:00 期间可排。

> 若只填 week=6 表示仅每周六这个时段不可用；date 与 week 都填时以 date 为准。

***

### 5.5 `shift_config.csv` + `shift_change_time.csv` —— 班次与交接班

**用途**：`shift_config.csv` 定义一天有几个班、几点换班；`shift_change_time.csv` 定义交接班时间段（这段时间不安排加工，用于报表里标班次）。

**shift\_config 示例（2 行）**：

| shift_name | start_time |
| ---------- | ---------- |
| 白班 | 08:30 |
| 夜班 | 20:30 |

解读：一天两个班：白班 8:30 开始、夜班 20:30 开始。

**shift\_change\_time 示例（2 行）**：

| start_time | end_time | day |
| ---------- | -------- | --- |
| 20:30 | 21:30 | -1 |
| 08:30 | 09:30 | -1 |

解读：每天（-1）20:30~~21:30 和 8:30~~9:30 是交接班时段，此时段内不安排加工。

***

### 5.6 `step_time_window.csv` —— 步骤允许作业的时间段

**用途**：某些步骤只能在特定时间段做（例如需要人员值守的步骤只在白天做，或 FTF 转运只在某时段）。

**列说明**：

| 列名                                            | 含义                                 |
| --------------------------------------------- | ---------------------------------- |
| `step_name`                                   | 步骤名                                |
| `start_time` / `end_time`                     | 允许开始/结束的时段                         |
| `day`                                         | `-1`=每天；`1~7`=周几；`YYYY/MM/DD`=指定日期 |
| `end_start_time` / `end_end_time` / `end_day` | 可选的"结束条件"窗口（复杂约束用，一般留空）            |

**示例（1 行）**：

| step_name | start_time | end_time | day | end_start_time | end_end_time | end_day |
| --------- | ---------- | -------- | --- | -------------- | ------------ | ------- |
| A008-R1-FTF-INPUT-TO-OUTPUT | 09:30 | 20:00 | -1 | | | |

解读：步骤 `A008-R1-FTF-INPUT-TO-OUTPUT` 每天只能在 09:30\~20:00 之间作业，其它时间不排。

***

### 5.7 `ftf_qty_change.csv` —— FTF 环节进出数量变化

**用途**：某些产品在 FTF（转贴）环节，因为**转贴 map 不同**，进入的数量和转贴后的数量不一样（例如 681 片进、564 片出），系统据此按转贴后的数量来排后续步骤。

**列说明**：`product_name`、`input_number`（进）、`output_number`（出）、`change_step`（发生数量变化的步骤）。

**示例（1 行）**：

| product_name | input_number | output_number | change_step |
| ----------- | ------------ | ------------- | ----------- |
| A008-MS | 681 | 564 | A008-R1-FTF-INPUT-TO-OUTPUT |

解读：A008-MS 产品在 `FTF-INPUT-TO-OUTPUT` 这一步，转贴前 681 片、转贴后 564 片（因转贴 map 不同），系统按转贴后的 564 片排后续。

### 5.8 `lot_constraints.csv` —— 批次间联动约束

**用途**：批次之间有联动关系——比如"后一批 `real1` 要等前一批 `PC1` 的某一步做完才能开始自己对应的某一步"。

**列说明**（五列关系声明：`lot1 | step1 | lot2 | step2 | mod`）：

| 列名   | 含义                                                          |
| ----- | ----------------------------------------------------------- |
| `lot1` | 被约束的批次（旧列 `lot_name`）                                       |
| `step1` | 被约束批次的衔接步（旧列 `start_step`）：等满足条件后从这一步开始            |
| `lot2` | 参照批次（旧列 `reference_lot`）：等谁                                  |
| `step2` | 参照批次的步骤（旧列 `reference_step`）：等到它做完                            |
| `mod` | 偏移/修饰（旧列 `start_mod`）：空/`0`=无；`0.5`/`1`/`2`/`4`=几小时后；`shift`=下一班次；`shift_day`=下一白班；`lead`=领导衔接（见下方） |

注：`hold_period_N_start/end`（可选的"扣留时段"强制该批某时段不可动）仍受支持，列可省略。

**示例（2 行）**：

| lot1 | step1 | lot2 | step2 | mod |
| -------- | -------- | -------- | -------- | --------- |
| real1 | A005-R1-FC-REFLOW | PC1 | A005-P1-FC-REFLOW | 0 |
| real1 | A005-R1-UF-DISPENSE | PC1 | A005-P1-UF-DISPENSE | 0 |

解读：批次 `real1` 的 `A005-R1-FC-REFLOW` 这一步，必须等参照批 `PC1` 的 `A005-P1-FC-REFLOW` 完成后才能开始（start\_mod=0，无偏移）；同理它的 `A005-R1-UF-DISPENSE` 要等 `PC1` 的 `A005-P1-UF-DISPENSE`。

**lead 领导衔接（`start_mod=lead`）**

在少数关键 step 上，让**领导批 lot1** 的 `step1` 做完后，**配套批 lot2** 的 `step2` **背靠背紧跟着做**（lot1 恒领先），且全程不超任何区间 Q-time、不在运行中的紧 Q 窗口内空等。同用五列声明：

| lot1 | step1 | lot2 | step2 | mod |
| -------- | -------- | -------- | -------- | -------- |
| real1 | A005-R1-UF-DISPENSE | PC1 | A005-D1-UF-DISPENSE | lead |

含义：`PC1` 的 `A005-D1-UF-DISPENSE` **尾随** `real1` 的 `A005-R1-UF-DISPENSE`（`PC1` 不早于 `real1` 做完该步）。若 `real1` 的 `step1` 前后有多段连续 Q-time（如 UF-BAKE→PLASMA→DISPENSE→CURE），系统会以 `PC1` 该步开始时刻为锚，把 `real1` 上游链**按 Q 回拉对齐**——`real1` 不会提前做完停在 `DISPENSE` 前空等超 Q，而是整条链顺流与配套批相接。
- 数据体检：`lot1`/`lot2` 必须在批次表存在、流程必须含对应衔接步、lead 与普通引用不得成环；`lot1` 热启动太靠后（已越过 step1）时对 lot1 侧回拉失效并标注。

### 5.9 `manual_adjust.csv` —— 手动调整（网页生成）

**用途**：排程后手工干预——把某 Lot 某步**延后**到指定时间（delay），或**精确锁定**在某时间（pin）。建议在报表页"手动调整"界面操作，会自动写回此表。

**列说明**：

| 列名          | 含义                            |
| ----------- | ----------------------------- |
| `lot_name`  | 批次号                           |
| `step_name` | 步骤名，留空=该 Lot 所有未排步骤都生效        |
| `delay_to`  | 目标时间（YYYY/MM/DD HH:MM）        |
| `mode`      | `delay`=不早于该时间；`pin`=精确锁定在该时间 |

**示例（2 行）**：

| lot_name | step_name | delay_to | mode |
| -------- | --------- | -------- | ---- |
| CPU先导 | A008-R1-DPS-MOUNT | 2026/8/25 14:00 | delay |
| DDR1 | | 2026/8/25 09:00 | pin |

解读：批次 `CPU先导` 的 `A008-R1-DPS-MOUNT` 不早于 8/25 14:00 开始（delay）；批次 `DDR1` 的所有未排步骤精确锁定在 8/25 09:00（pin）。

***

### 5.10 `optimizer_config.json` —— 算法参数

**用途**：控制排程优化算法的强度（迭代次数等）。可在网页"算法配置"里改并保存。默认内容：

```json
{
  "max_iterations": 40,
  "resolve_max_iterations": 10
}
```

解读：`max_iterations`=算法最多迭代 40 轮找更优解（越大越慢但结果越好）；`resolve_max_iterations`=冲突消解最多 10 轮。一般不用改，追求更好排程质量时可调大。

## 7. 报表与辅助功能使用场景

进入 **可视化报表** 页面（`/reports`），主要功能及适用场景：

| -------------- | --------------------------- | -------------------------------------------- |
| **生成排程报表**     | 数据维护好后，第一次正式排程              | 点【生成排程报表】，产出各 Lot 每步的开始/结束时间、设备、班次           |
| **数据体检**       | 排程前先自查数据问题（缺步骤、缺 CT、引用不存在等） | 点【数据体检】，按"严重问题/建议修复"逐条处理                     |
| **多方案快照对比**    | 想从多个随机方案里挑最优                | 批量生成多个快照，看评分/延期数挑最优，最优方案自动导出 Excel           |
| **下载 Excel**   | 把排程结果发给产线/存档                | 点【下载 Excel 报表】                               |
| **甘特图（设备/批次）** | 直观看设备负载、批次时间线               | 生成后按设备或批次筛选查看，支持交互缩放                         |
| **交期反推**       | 客户给定交期，看当前能不能做到、每步最晚什么时候开始  | 输入 Lot 和期望完工时间，反推每步最晚时间，可一键设为"精确锁定"          |
| **手动调整**       | 对个别步骤强制延后或锁定                | 选 Lot+步骤+时间，可生成 `manual_adjust.csv`          |
| **算法配置**       | 想调优排程质量/速度                  | 顶部【算法配置】调迭代次数等参数并保存到 `optimizer_config.json` |

### 7.1 交期反推（期望完工时间 → 各步最晚开始）

**用途**：客户给定一个"期望完工时间"（交期），你想知道这个 Lot 从当前步骤开始能不能在交期内做完；如果能，最晚每步什么时候开始才来得及。

**怎么用**：

1. 先生成排程报表；
2. 在"手动调整排程"卡片点【交期反推】；
3. 从 **Lot 下拉框** 选择要查的批次（默认选第一个）；
4. 输入期望完工时间（`yyyy/mm/dd HH:MM`），点【反推】。

**结果说明**：

* **粗略最早计划**：从该 Lot 的"就绪时刻"（`lot_list.csv` 里填了 `start_time` 就用它，否则从现在算起）无设备竞争正推，得到各步最早开始/结束，最后一步结束即"粗略最早完工"。

* **最晚开始**：从期望完工时间往前反推，得到各步最晚开始/结束，满足交期的前提下最迟不能晚于此开始。

* 顶部标签显示"交期可行（粗略）"或"交期紧张：粗略最早完工 xxx 晚于交期"。

* 点【锁定末步最晚开始】可把末步设为"精确锁定"（pin），重新生成排程后尽量按此贴近交期。

> ⚠️ **注意（重要）**：反推结果是**粗略估算，未考虑设备竞争、班次、Q-time 链内压缩**等约束，只按"CT + 步间等待"算。实际排程会受设备负载影响，可能比反推的更晚。所以反推结果用于"能不能做到"的初步判断，最终以排程报表为准。

### 7.2 手动调整（延后/锁定步骤 + 规则文件管理）

**用途**：对个别步骤强制干预——**延后**（delay：不早于某时间开始）或**精确锁定**（pin：尽量精确落在某时间开始）。

**两种维护规则的方式**：

1. **逐条添加**：在"排程步骤明细"表里点某行【延迟】按钮，设置目标时间与模式，点【确认并重新排程】；
2. **逐条删除**：在"当前调整规则"表里点某行【删除】，会弹出确认框，**只删除该条**（按 Lot+步骤+时间+模式精确匹配，不会误删其它规则）。

> 说明：以上操作只改"内存规则"（即当前输入），未点【保存到文件】前不影响 `data/manual_adjust.csv`；点【保存到文件】后写回文件。规则生效需要点【重新生成】完整重排。批量维护规则也可直接在"数据管理"页编辑 `manual_adjust.csv` 表。

**标准操作流程（每天/每次排程）**：

```
① 更新 lot_list.csv（新增批次、更新 running 状态/交期）
② 按需更新流程/CT/设备/班次等配置
③ 进报表页 → 数据体检（有错先改） → 生成排程报表
④ 查看延期/告警 → 需要时手动调整 / 交期反推 → 重新生成
⑤ 多方案对比挑最优 → 下载 Excel / 查看甘特图 → 分发
```

## 8. 常见问题与注意事项

| #  | 问题                  | 说明 / 处理                                                                  |
| -- | ------------------- | ------------------------------------------------------------------------ |
| 1  | 改了 CSV 不生效          | 网页编辑后要点【保存】；直接改文件的话刷新页面即可（程序每次排程都重新读文件）                                  |
| 2  | 报"找不到 CT / 没有 flow" | 多半是 flow\.csv 新增了步骤但 step\_ct.csv 没有对应 CT。系统会自动补全并回写 step\_ct.csv，重新生成即可 |
| 3  | 产品名不一致              | lot\_list、flow、step\_ct、qtime 里的 `product_name` 必须完全一致（含大小写），否则该批次排不出    |
| 4  | 优先级格式               | 必须写成 `外部-内部`（如 `1-1`），不要写成 `1` 或 `1,1`                                   |
| 5  | 时间格式                | 所有日期时间统一 `YYYY/MM/DD HH:MM`；时刻统一 `HH:MM`                                 |
| 6  | 优先级数字               | 数字越小越优先（1 最高）                                                            |
| 7  | 合批限制                | `special_eqp` 合批时同一批内的产品名与步骤名必须相同，系统不会混批                                 |
| 8  | running\_time       | 只对 `lot_state=running` 的 Lot 有效，单位分钟；不影响开始时间，只缩短当前步骤剩余时间；≥CT 时按 0 处理     |
| 9  | 交期/延期               | 只有 `lot_list` 里填了 `planned_end` 的批次才会参与延期统计                              |
| 10 | 数据备份                | `data/` 是整个系统的"生产资料"，建议定期整体备份；整个目录搬到别的电脑即可复用                             |
| 11 | 报表出现"[排程合理性]"告警 | 排程结束后系统会对结果做合理性检测（只提示、不改变结果）。目前只检测三类：lot_constraints 引用环、引用环雪崩自动回退、引用步骤在流程中不存在；出现时请核查 `lot_constraints.csv` 配置 |
